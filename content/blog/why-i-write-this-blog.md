สวัสดีครับ ผม Kasidit Wansudon เป็น full-stack developer สัญชาติไทย นี่คือโพสต์แรกของบล็อกนี้ และผมตั้งใจว่าจะเขียนทุกสัปดาห์ ในโพสต์นี้ผมอยากเล่าว่าทำไมถึงเริ่มเขียนบล็อกทุกสัปดาห์แบบ learning in public จะเขียนเรื่องอะไรบ้าง และอยากชวนคุณมาทักทายกันใน guestbook

## ผมคือใคร แบบสั้น ๆ

ก่อนเขียนโค้ด ผมทำงานด้านโลจิสติกส์และงานก่อสร้าง จากนั้นเรียน Software Engineering ที่มหาวิทยาลัยราชภัฏศรีสะเกษ และเริ่มรับงาน freelance ตั้งแต่ระหว่างเรียน ต่อมาทำงานเป็น Mobile Developer เขียน Flutter POS และปัจจุบันเป็น full-stack developer ทำเครื่องมือภายในสำหรับการดำเนินงานใน 12 ประเทศ ด้วย Laravel, Vue, MySQL และ cloud

เส้นทางนี้ไม่ได้ตรงนัก และผมคิดว่านั่นเป็นเหตุผลหนึ่งที่อยากเขียน

## ทำไมต้องเขียน

### 1. เขียนเพื่อคิดให้ชัด

ผมพบว่าตัวเองเข้าใจเรื่องหนึ่งจริงก็ต่อเมื่ออธิบายให้คนอื่นฟังได้ หลายครั้งที่ผมคิดว่ารู้เรื่องหนึ่งดีแล้ว แต่พอลองเขียนออกมากลับติดตั้งแต่ย่อหน้าที่สอง การเขียนบังคับให้ผมเติมช่องว่างที่ไม่รู้ว่ามี

### 2. Learning in public

learning in public คือการแบ่งปันสิ่งที่กำลังเรียนรู้ระหว่างทาง ไม่ใช่รอจนเป็นผู้เชี่ยวชาญก่อน ข้อดีคือ

- คนที่อยู่ช่วงเดียวกับเราได้ประโยชน์ เพราะเรายังจำได้ว่าตอนไม่รู้เป็นอย่างไร
- คนที่รู้มากกว่าช่วยชี้จุดที่เราเข้าใจผิดได้
- มีบันทึกให้ตัวเองกลับมาอ่านในอนาคต

ผมจะพยายามเขียนอย่างซื่อตรง ทั้งสิ่งที่ได้ผลและสิ่งที่พัง เพราะบทเรียนจากความผิดพลาดมักมีค่ามากกว่า

### 3. ตอบคำถามเดิมครั้งเดียว

ในงานผมมักถูกถามคำถามคล้าย ๆ กันซ้ำ เช่น จะตั้ง index อย่างไร จะ deploy อย่างไรให้ rollback ได้ จะใช้ AI เขียนโค้ดอย่างไรไม่ให้พัง การเขียนเป็นโพสต์ทำให้ผมตอบละเอียดได้ครั้งเดียว แล้วส่งลิงก์ให้คนถัดไป

## หัวข้อที่จะเขียน

ผมแบ่งหัวข้อหลักไว้สามกลุ่ม

### AI ในงานพัฒนาซอฟต์แวร์

ผมใช้ AI ช่วยเขียนโค้ดทุกวัน และเจอทั้งด้านที่ช่วยได้มาก และด้านที่ทำให้เสียเวลา เช่น AI แต่งตัวแปรที่ไม่มีอยู่จริง หรือแก้ bug วนไปมาไม่จบ ผมจะเขียนถึงวิธีทำงานกับ AI ให้ได้ผล กฎที่ผมใช้ และสิ่งที่ไม่ควรเชื่อ

### การเขียนโค้ดและระบบหลังบ้าน

เรื่องที่ผมทำจริงทุกวัน เช่น MySQL query optimization, Laravel, การ deploy, Git workflow, การออกแบบระบบที่ใช้หลายประเทศ รวมถึงการมองย้อนงานเก่า เช่น Flutter POS ที่ sync ด้วย MQTT

### การทำงานเป็นทีมและการนำทีม

ยิ่งทำงานนานขึ้น ผมยิ่งเห็นว่าปัญหาส่วนใหญ่ไม่ได้อยู่ที่โค้ด แต่อยู่ที่การสื่อสาร การส่งต่องาน และการตัดสินใจร่วมกัน ผมเพิ่งเริ่มเรียนรู้เรื่องนี้ และอยากเขียนไปพร้อมกับการเรียนรู้

## รูปแบบของแต่ละโพสต์

ผมตั้งกติกาให้ตัวเองไว้ไม่กี่ข้อ

- **เขียนจากงานจริง** ไม่เขียนเรื่องที่ยังไม่เคยลงมือทำ
- **มีสิ่งที่เอาไปใช้ได้** ทุกโพสต์ควรมีขั้นตอน checklist โค้ด หรือวิธีคิดที่นำไปใช้ต่อได้
- **ไม่ยาวเกินจำเป็น** อ่านจบในเวลาพักกาแฟหนึ่งแก้ว
- **ไม่เปิดเผยข้อมูลภายในของที่ทำงาน** เล่าบทเรียนได้ แต่ไม่เล่ารายละเอียดที่เป็นความลับ

ตัวอย่างโครงของโพสต์ที่ผมใช้ร่างทุกครั้ง

```text
1. ปัญหาที่เจอ (ทำไมเรื่องนี้สำคัญ)
2. สิ่งที่ลองแล้วไม่ได้ผล
3. สิ่งที่ได้ผล พร้อมขั้นตอนหรือโค้ด
4. ข้อควรระวัง
5. สรุป
```

## ทำไมต้องทุกสัปดาห์

ความถี่ทุกสัปดาห์บังคับให้ผมไม่รอให้ทุกอย่างสมบูรณ์ ถ้าเขียนเดือนละครั้ง ผมจะใช้เวลาขัดเกลาจนไม่ได้ปล่อย ถ้าเขียนทุกวัน ผมจะไม่มีเวลาทำงานจริงที่จะเอามาเขียน หนึ่งโพสต์ต่อสัปดาห์จึงเป็นจุดสมดุลที่ผมคิดว่าทำได้ยาว ๆ

แน่นอนว่าจะมีบางสัปดาห์ที่งานหนักจนเกือบไม่ได้เขียน ผมเลยเก็บรายการหัวข้อสำรองไว้เสมอ

## มาทักทายกันใน guestbook

บล็อกนี้ยังไม่มีระบบคอมเมนต์ แต่มี [guestbook](/guestbook) ให้ทิ้งข้อความไว้ได้ อยากให้ผมเขียนเรื่องอะไร มีคำถามเกี่ยวกับงานที่ทำ หรือแค่อยากทักทาย ก็เขียนทิ้งไว้ได้เลย ผมอ่านทุกข้อความ และหัวข้อที่มีคนถามเข้ามาจะได้รับความสำคัญก่อน

## สรุป

ผมเริ่มเขียนบล็อกทุกสัปดาห์เพราะอยากคิดให้ชัดขึ้น อยากเรียนรู้แบบ learning in public และอยากตอบคำถามเดิมให้ละเอียดเพียงครั้งเดียว หัวข้อหลักคือ AI ในงานพัฒนาซอฟต์แวร์ การเขียนโค้ดและระบบหลังบ้าน และการทำงานเป็นทีม ขอบคุณที่อ่านมาถึงตรงนี้ แล้วเจอกันในโพสต์หน้าครับ
