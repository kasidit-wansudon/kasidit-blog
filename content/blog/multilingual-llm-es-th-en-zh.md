ทีมที่ผมทำงานด้วยที่เม็กซิโกใช้ภาษาสเปนเป็นหลัก แต่มีทั้งคนไทย คนจีน และคนที่สื่อสารด้วยภาษาอังกฤษ ตอนสร้าง AI sales agent ที่ตอบผ่าน DingTalk โจทย์จึงไม่ใช่แค่ "ให้ AI ตอบได้" แต่ต้องเป็น AI assistant หลายภาษาที่ตอบได้ดีเท่ากันทั้งสเปน ไทย อังกฤษ และจีน

LLM รุ่นใหม่เก่งหลายภาษาอยู่แล้ว แต่ "เก่งในการทดสอบ" กับ "ใช้งานจริงได้ดี" ต่างกันมาก โพสต์นี้รวมสิ่งที่ผมเรียนรู้จากการทำให้มันใช้ได้จริง

## ปัญหาที่เจอบ่อยในระบบหลายภาษา

- ผู้ใช้ถามภาษาสเปน แต่ได้คำตอบภาษาอังกฤษ
- ชื่อรุ่นสินค้าหรือศัพท์ธุรกิจถูกแปลจนไม่มีใครรู้จัก
- คำถามภาษาไทยหรือจีนค้นหาข้อมูลไม่เจอ เพราะเอกสารต้นทางเป็นภาษาอังกฤษ
- คุณภาพคำตอบภาษาหนึ่งตกลงหลังแก้ prompt โดยไม่มีใครสังเกต

ทั้งสี่ข้อนี้แก้ได้ด้วยสามเรื่องหลัก คือ language detection, glossary และการทดสอบแยกภาษา

## Language detection: อย่าปล่อยให้ model เดาเอง

วิธีที่ง่ายที่สุดคือเขียนใน prompt ว่า "ตอบภาษาเดียวกับผู้ใช้" ซึ่งได้ผลเกือบทุกครั้ง แต่ "เกือบ" ไม่พอเมื่อคำถามสั้นมาก หรือมีชื่อสินค้าภาษาอังกฤษปนอยู่ เช่น คำถามภาษาสเปนสามคำที่มีชื่อรุ่นสองคำ

ผมเลยตรวจภาษาในโค้ดก่อน แล้วส่งผลให้ model เป็นคำสั่งชัดเจน

```typescript
type Lang = "es" | "th" | "en" | "zh";

export function detectLanguage(text: string, fallback: Lang = "es"): Lang {
  const thai = (text.match(/[฀-๿]/g) ?? []).length;
  const cjk = (text.match(/[一-鿿]/g) ?? []).length;
  if (thai > 0 && thai >= cjk) return "th";
  if (cjk > 0) return "zh";

  const lower = text.toLowerCase();
  const spanishHints = /[ñáéíóú¿¡]|\b(cuánto|cuántos|ventas|mes|tienda|qué|cómo|dónde)\b/;
  if (spanishHints.test(lower)) return "es";

  const latinWords = lower.match(/[a-z]+/g) ?? [];
  return latinWords.length > 0 ? "en" : fallback;
}
```

ไทยกับจีนตรวจง่ายจากช่วง Unicode ส่วนสเปนกับอังกฤษยากกว่าเพราะใช้อักษรเดียวกัน ผมใช้คำบอกใบ้กับตัวอักษรพิเศษ และตั้ง fallback เป็นภาษาหลักของผู้ใช้กลุ่มใหญ่ที่สุด อีกทางที่ดีกว่าคือเก็บภาษาที่ผู้ใช้ตั้งไว้ในโปรไฟล์ แล้วใช้การตรวจเป็นแค่ตัวเสริม

จากนั้นใส่ใน system prompt ตรง ๆ ว่า `Respond in: es` แทนการบอกให้ model เดา

## Glossary: ศัพท์ที่ห้ามแปล และศัพท์ที่ต้องแปลแบบเดียว

ปัญหาที่ทำให้ผู้ใช้ไม่เชื่อถือ AI เร็วที่สุดคือศัพท์ผิด ผมแบ่ง glossary เป็นสองกลุ่ม

**ห้ามแปล** ชื่อรุ่นสินค้า ชื่อระบบภายใน ชื่อรายงาน รหัสต่าง ๆ พวกนี้ต้องคงรูปเดิมทุกภาษา

**แปลแบบเดียวเสมอ** ศัพท์ธุรกิจ เช่น sell-in, sell-out, สต็อก, ใบสั่งซื้อ ต้องกำหนดคำแปลที่ทีมใช้จริงในแต่ละภาษา ไม่ปล่อยให้ model เลือกคำพ้องความหมายไปเรื่อย ๆ

ผมเก็บ glossary เป็นไฟล์ JSON แล้วแทรกเฉพาะส่วนของภาษาที่ตรวจพบเข้าไปใน prompt ไม่ต้องใส่ทั้งสี่ภาษา เพื่อประหยัด token และลดความสับสน

glossary ยังช่วยฝั่ง retrieval ด้วย เมื่อผู้ใช้ถามด้วยคำภาษาไทยหรือจีน ระบบ map กลับเป็นคำหลักภาษาอังกฤษก่อนค้นหา ทำให้หาเอกสารเจอแม้ต้นฉบับจะเป็นคนละภาษา

## รูปแบบตัวเลข วันที่ และสกุลเงิน

เรื่องเล็กที่ผู้ใช้สังเกตทันที เช่น ภาษาสเปนในเม็กซิโกกับภาษาไทยแสดงตัวเลขและวันที่ต่างกัน ผมไม่ให้ model จัดรูปแบบเอง แต่ให้ tool คืนค่าดิบ แล้วจัดรูปแบบด้วย `Intl.NumberFormat` และ `Intl.DateTimeFormat` ตาม locale ก่อนส่งเข้า model วิธีนี้ทั้งแม่นกว่าและลดโอกาสที่ model จะแต่งตัวเลขผิด

## ทดสอบแยกตามภาษา

นี่คือจุดที่ทีมส่วนใหญ่ข้าม และเป็นจุดที่สำคัญที่สุด ผมทำ test set ที่มีคำถามชุดเดียวกันในสี่ภาษา แล้ววัดผลแยกกัน

- คำตอบเป็นภาษาที่ถูกต้องหรือไม่
- ศัพท์ใน glossary ถูกใช้ตรงตามที่กำหนดหรือไม่
- ตัวเลขในคำตอบตรงกับผลจาก tool หรือไม่
- ความยาวและน้ำเสียงเหมาะสมหรือไม่

สามข้อแรกตรวจอัตโนมัติได้ ข้อสุดท้ายต้องให้คนที่ใช้ภาษานั้นจริงช่วยดู ในทีมที่ทำงานสี่ภาษา ผมขอให้แต่ละคนรีวิวเฉพาะภาษาของตัวเองไม่กี่เคสต่อสัปดาห์ ได้ผลดีกว่าให้คนคนเดียวอ่านทุกภาษาผ่าน machine translation

ทุกครั้งที่แก้ prompt ต้องรันครบทั้งสี่ภาษา เพราะการแก้ที่ทำให้ภาษาหนึ่งดีขึ้น บางครั้งทำให้อีกภาษาแย่ลงโดยไม่รู้ตัว เรื่องการใช้ trace ช่วยหาจุดพัง ผมเขียนไว้ใน [รีวิวคุณภาพคำตอบ LLM จาก trace](/blog/trace-based-llm-answer-quality)

## บทเรียนจากการทำงานหลายภาษา

การทำงานกับทีมสี่ภาษาทำให้ผมเห็นว่า ภาษาไม่ใช่แค่การแปล แต่เป็นเรื่องความคาดหวังด้วย บางภาษาผู้ใช้ชอบคำตอบสั้นตรงประเด็น บางภาษาคาดหวังความสุภาพมากกว่า prompt ที่ดีจึงควรมีคำแนะนำเรื่องน้ำเสียงแยกตามภาษาเล็กน้อย ไม่ต้องยาว แต่ต้องมี เรื่องการทำงานกับคนหลายภาษาในทีม ผมเล่าไว้ใน [นำทีมในสี่ภาษา](/blog/leading-team-in-four-languages)

## สรุป

AI assistant หลายภาษาจะตอบดีได้จริงเมื่อเราไม่ปล่อยให้ model เดาเรื่องสำคัญเอง ตรวจภาษาในโค้ดแล้วสั่งให้ชัด ใช้ glossary คุมศัพท์ทั้งฝั่งคำตอบและการค้นหา จัดรูปแบบตัวเลขก่อนส่งให้ model และทดสอบแยกทุกภาษาทุกครั้งที่เปลี่ยน prompt สี่ข้อนี้ทำให้ผู้ใช้ทุกภาษาได้ประสบการณ์ที่ใกล้เคียงกัน
