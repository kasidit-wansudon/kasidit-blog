ต้นปี 2026 ผมย้ายจาก Bangkok มาทำงานที่ Mexico City ในฐานะ developer ที่เดิมดูแลระบบให้ OPPO หลายประเทศจากกรุงเทพฯ ตอนนี้มานั่งใกล้ user จริงของระบบ บทความนี้ไม่ใช่รีวิวเมือง แต่เป็นบันทึกเชิงปฏิบัติว่าย้ายมาเป็น developer ในต่างประเทศ ต้องจัดการอะไรบ้างเพื่อให้ทำงานต่อได้ทันที ตั้งแต่อุปกรณ์ เวลา ภาษา ไปจนถึงการรักษา productivity

## ก่อนย้าย: เตรียม work setup ให้ "พกไปได้"

สิ่งที่ผมทำก่อนขึ้นเครื่องคือทำให้งานทั้งหมดไม่ผูกกับเครื่องหรือเครือข่ายที่กรุงเทพฯ

- **Code ทุกอย่างอยู่ใน git remote** ไม่มี branch ที่อยู่แค่ในเครื่อง
- **Dotfiles และ config** เก็บเป็น repo แยก ติดตั้งเครื่องใหม่ได้ในไม่กี่คำสั่ง
- **Password manager และ 2FA** ตรวจว่า backup code ใช้ได้ และไม่ผูก 2FA กับเบอร์โทรที่อาจใช้ไม่ได้ในต่างประเทศ
- **VPN และสิทธิ์เข้า server** ทดสอบจากเครือข่ายอื่นก่อนเดินทาง เพราะ access บางอย่างผูกกับ IP เดิม
- **อุปกรณ์สำรอง** ปลั๊กแปลง (เม็กซิโกใช้ปลั๊กแบบ A/B 127V), สายชาร์จสำรอง, SSD สำรองข้อมูล

บทเรียนที่ได้คือ ถ้าเครื่องหายวันแรกที่ถึง ต้องกลับมาทำงานได้ภายในวันเดียว ถ้าไม่ได้ แปลว่า setup ยังไม่พร้อมย้าย

## Time zone: ต่างกัน 13 ชั่วโมง

Mexico City ช้ากว่ากรุงเทพฯ 13 ชั่วโมง (เม็กซิโกเลิกใช้ daylight saving แล้วในพื้นที่ส่วนใหญ่ ทำให้คำนวณง่ายขึ้น) แปลว่าเช้าของผมคือคืนของทีมที่ไทย และเย็นของผมคือเช้าของเขา

สิ่งที่ช่วยได้จริง

- **กำหนด overlap window ชัดเจน** ช่วงเช้าตรู่หรือช่วงเย็นของเม็กซิโกที่ตรงกับเวลาทำงานของเอเชีย ใช้สำหรับเรื่องที่ต้องคุยสด ส่วนเรื่องอื่นทำแบบ async
- **เขียนแทนพูด** เปลี่ยนคำถามที่เคยถามข้ามโต๊ะ เป็นข้อความที่มีบริบทครบ คนอ่านตอบได้โดยไม่ต้องถามกลับ
- **ระวัง timestamp ในระบบ** ทุกครั้งที่ดู log หรือ report ต้องรู้ว่าเป็นเวลา UTC, เวลาไทย หรือเวลาเม็กซิโก ผมตั้งให้ log และ database ใช้ UTC และแปลงเฉพาะตอนแสดงผล
- **Deploy window ต้องคิดใหม่** "หลังเลิกงาน" ของที่หนึ่งคือ "ชั่วโมงเร่งด่วน" ของอีกที่ ต้องดูว่า user หลักของระบบนั้นอยู่ประเทศไหน

## ภาษา: อังกฤษพอทำงานได้ แต่สเปนทำให้งานเดิน

ในที่ทำงาน ผมต้องสื่อสารด้วยอังกฤษ สเปน จีน และไทย ขึ้นกับว่าคุยกับใคร อังกฤษพอสำหรับคุยกับทีม tech แต่ user ฝั่ง operation จำนวนมากสะดวกสเปนมากกว่า

วิธีที่ผมใช้

- เรียนสเปนแบบ "ศัพท์ที่ใช้ในงาน" ก่อน เช่น คำที่อยู่บนหน้าจอระบบ, คำเกี่ยวกับคลังสินค้า, การอนุมัติ
- เขียนข้อความสำคัญเป็นอังกฤษก่อน แล้วใช้ AI ช่วยแปลเป็นสเปน แต่ขอให้คนในทีมช่วยตรวจในเรื่องที่ผิดไม่ได้
- ในระบบที่สร้าง ทำ i18n ตั้งแต่วันแรก ไม่ต้องรอมีคนขอ

เรื่องการนำทีมหลายภาษา ผมเขียนแยกไว้ใน [นำทีมใน 4 ภาษา](/blog/leading-team-in-four-languages)

## รักษา productivity ในช่วงปรับตัว

เดือนแรกคือช่วงที่ productivity ตกง่ายที่สุด เพราะทุกอย่างใหม่หมด ทั้งที่พัก การเดินทาง อาหาร และคนรอบตัว สิ่งที่ช่วยผม

**ทำ routine ให้เร็วที่สุด** เวลาตื่น เวลาเริ่มงาน เวลาออกกำลังกาย ล็อกให้ได้ภายในสัปดาห์แรก routine ทำให้สมองไม่ต้องตัดสินใจเรื่องเล็ก ๆ ทั้งวัน

**เลือกงานแรกให้เล็กและจบได้** อย่าเริ่มด้วยโปรเจกต์ใหญ่ เลือกงานที่ส่งมอบได้ในไม่กี่วัน เพื่อสร้างโมเมนตัมและความเชื่อใจกับทีมใหม่

**พักอย่างตั้งใจ** jet lag จาก 13 ชั่วโมงไม่ได้หายในวันเดียว ผมไม่ฝืนทำงานลึกในช่วงที่ร่างกายยังสับสนเวลา ใช้ช่วงนั้นทำงานที่ใช้สมองน้อย เช่น อ่านเอกสาร จัด inventory ระบบ

**ใช้ AI เป็นผู้ช่วย ไม่ใช่ทางลัด** ช่วงปรับตัว ผมใช้ Claude Code ช่วยอ่าน codebase ที่ไม่คุ้น และช่วยสรุปเอกสารภาษาสเปน แต่ทุกการเปลี่ยนแปลงยังต้องผ่านการตรวจและทดสอบจริง

**ความสูงของเมือง** Mexico City สูงประมาณ 2,200 เมตรจากระดับน้ำทะเล ช่วงแรกเหนื่อยง่ายกว่าปกติ ดื่มน้ำมากขึ้นและอย่าเพิ่งหักโหม

## Checklist สำหรับ developer ที่กำลังจะย้ายประเทศ

- งานทั้งหมดอยู่บน remote, ตั้งเครื่องใหม่ได้ภายในวันเดียว
- 2FA และ backup code ไม่ผูกกับเบอร์ที่อาจใช้ไม่ได้
- ทดสอบ VPN และ access จากเครือข่ายอื่นแล้ว
- รู้ overlap window กับทีมทุกฝั่ง
- log และ database ใช้ UTC
- เรียนศัพท์ภาษาท้องถิ่นที่ใช้ในงานก่อน
- วางงานแรกที่จบได้ในไม่กี่วัน

## สรุป

การย้ายจาก Bangkok ไป Mexico City ในฐานะ developer สำเร็จหรือไม่ ไม่ได้ขึ้นกับทักษะเขียนโค้ด แต่ขึ้นกับการเตรียม setup ให้พกไปได้ การจัดการ time zone ด้วยการทำงานแบบ async การเรียนภาษาที่ใช้ในงานจริง และการสร้าง routine ให้เร็ว ถ้าเตรียมสี่เรื่องนี้ไว้ดี สัปดาห์แรกในประเทศใหม่จะเป็นสัปดาห์ที่ได้งาน ไม่ใช่สัปดาห์ที่เสียไปกับการตามแก้ setup
