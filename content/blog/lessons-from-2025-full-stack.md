วันสุดท้ายของปีเป็นช่วงที่ผมชอบนั่งทบทวนว่าปีที่ผ่านมาได้เรียนรู้อะไร ปี 2025 ผมทำงานเป็น full-stack developer สร้างเครื่องมือภายในที่ใช้กับการดำเนินงานใน 12 ประเทศ ด้วย Laravel, Vue, MySQL, AWS, Cloudflare และ GitLab CI งานแบบนี้สอนผมหลายเรื่องที่ไม่เคยเจอตอนทำระบบให้ลูกค้ารายเดียวหรือประเทศเดียว โพสต์นี้รวมบทเรียนที่ผมคิดว่าใช้ได้กับคนที่กำลังทำระบบข้ามประเทศเหมือนกัน

## 1. Timezone ไม่ใช่รายละเอียด แต่เป็นการออกแบบ

ปัญหาแรกที่เจอเมื่อระบบเดียวถูกใช้หลายประเทศคือคำถามง่าย ๆ อย่าง "ยอดขายของวันนี้" วันนี้ของใคร

กติกาที่ผมยึดหลังจากเจ็บมาแล้ว

- เก็บเวลาใน database เป็น UTC เสมอ
- แปลงเป็นเวลาท้องถิ่นตอนแสดงผลและตอนสร้าง report เท่านั้น
- report รายวันต้องระบุชัดว่าตัดรอบตาม timezone ไหน

```php
// ตัดรอบ "วันนี้" ตาม timezone ของประเทศ แล้วแปลงกลับเป็น UTC ก่อน query
$tz    = $country->timezone; // เช่น 'Asia/Bangkok'
$start = now($tz)->startOfDay()->utc();
$end   = now($tz)->endOfDay()->utc();

$total = Order::whereBetween('created_at', [$start, $end])->sum('total');
```

โค้ดไม่กี่บรรทัดนี้ป้องกันการโต้เถียงเรื่องตัวเลขไม่ตรงกันได้หลายครั้ง

## 2. ภาษาและรูปแบบตัวเลขต้องคิดตั้งแต่วันแรก

การเพิ่มภาษาทีหลังเจ็บกว่าการเตรียมไว้ตั้งแต่ต้นเสมอ ข้อความทุกตัวควรอยู่ในไฟล์แปลตั้งแต่บรรทัดแรก แม้ตอนนั้นจะมีภาษาเดียวก็ตาม และอย่าลืมว่ารูปแบบวันที่ ตัวเลข และสกุลเงินต่างกันในแต่ละประเทศ ผมเลิก format ตัวเลขด้วยมือ แล้วใช้ API ที่รองรับ locale แทน

## 3. ข้อมูลโต ระบบช้าลงเอง

หน้าจอที่เปิดเร็วตอนต้นปี ช้าลงอย่างเห็นได้ชัดตอนกลางปีโดยไม่มีใครแก้โค้ด เพราะข้อมูลจากหลายประเทศสะสมเร็วกว่าที่คิด ปีนี้ผมลด latency ของ query หลักได้กว่า 40% ด้วยการกลับไปทำพื้นฐาน ทั้ง composite index และการกำจัด N+1

บทเรียนคือ performance ไม่ใช่งานที่ทำครั้งเดียวจบ ต้องมีการวัดเป็นระยะ ไม่ใช่รอให้ผู้ใช้บ่น

## 4. Deploy ที่น่าเบื่อคือ deploy ที่ดี

เมื่อมีผู้ใช้หลายประเทศ ไม่มีช่วงเวลาไหนที่ "ไม่มีใครใช้ระบบ" อย่างแท้จริง การ deploy จึงต้องคาดเดาได้และ rollback ได้เร็ว สิ่งที่ช่วยผมได้มากในปีนี้

- ให้ GitLab CI รัน test และ build ทุกครั้ง ไม่ข้ามแม้จะเป็นการแก้เล็ก ๆ
- migration ต้องเข้ากันได้กับโค้ดเวอร์ชันก่อน เพื่อให้ rollback โค้ดได้โดยไม่ต้อง rollback database
- จดสิ่งที่ deploy ทุกรอบ ไม่ว่าจะเล็กแค่ไหน

## 5. Cache ช่วยได้มาก ถ้ารู้ว่าจะ invalidate เมื่อไร

ผมใช้ Cloudflare กับ asset และ API บางส่วน ความเร็วดีขึ้นชัดเจนสำหรับผู้ใช้ที่อยู่ไกลจาก server แต่ก็เจอปัญหาคลาสสิกคือข้อมูลเก่าค้าง บทเรียนคือ ก่อน cache อะไรต้องตอบให้ได้ก่อนว่าข้อมูลนั้นเปลี่ยนเมื่อไร และเราจะล้าง cache อย่างไร ถ้าตอบไม่ได้ก็อย่าเพิ่ง cache

## 6. การสื่อสารสำคัญกว่าโค้ด

งานที่ผมใช้เวลามากกว่าที่คาดไม่ใช่การเขียนโค้ด แต่เป็นการทำความเข้าใจว่าแต่ละประเทศทำงานต่างกันอย่างไร กระบวนการที่ดูเหมือนกันบนกระดาษ ในทางปฏิบัติมีข้อยกเว้นเฉพาะที่เสมอ

สิ่งที่ผมเริ่มทำและได้ผล

- ขอให้ผู้ใช้เล่าขั้นตอนจริงพร้อมตัวอย่างข้อมูล ไม่ใช่แค่บอกว่าอยากได้ฟีเจอร์อะไร
- ส่ง demo เร็ว ๆ แม้ยังไม่สมบูรณ์ เพราะคนชี้ปัญหาบนหน้าจอได้ง่ายกว่าบนเอกสาร
- เขียนสรุปสั้น ๆ หลังประชุมทุกครั้ง เพื่อให้ทุกคนเข้าใจตรงกัน

## 7. AI เป็นตัวคูณ ไม่ใช่ตัวแทน

ปีนี้ผมใช้ AI ช่วยเขียนโค้ดมากขึ้นเรื่อย ๆ มันช่วยเร่งงานที่น่าเบื่อได้มาก แต่ผมก็เคยเสียเวลากับการแก้ bug ที่ AI สร้างขึ้นจากการเดา สิ่งที่ได้เรียนรู้คือ AI คูณสิ่งที่เรามีอยู่ ถ้าเรามีวินัยในการตรวจ มันคูณความเร็ว ถ้าเราไม่ตรวจ มันคูณความผิดพลาด

## สิ่งที่อยากทำต่างไปในปีหน้า

- เขียนเอกสารระหว่างทำงาน ไม่ใช่หลังงานเสร็จ
- วัด performance เป็นรอบ ไม่ใช่รอให้มีคนบ่น
- เขียนบล็อกสม่ำเสมอ เพื่อบังคับตัวเองให้สรุปสิ่งที่เรียนรู้ ซึ่งเป็นเหตุผลเดียวกับที่ผม[เริ่มเขียนบล็อกนี้](/blog/why-i-write-this-blog)

## สรุป

บทเรียนปี 2025 ของผมในฐานะ full-stack developer ที่ทำระบบให้ 12 ประเทศ คือ เก็บเวลาเป็น UTC, เตรียมเรื่องภาษาตั้งแต่วันแรก, วัด performance เป็นระยะ, ทำให้ deploy น่าเบื่อและ rollback ได้, cache เมื่อรู้วิธี invalidate, ลงทุนกับการสื่อสาร และใช้ AI อย่างมีวินัย ทั้งหมดนี้ไม่ใช่เรื่องใหม่ แต่เป็นสิ่งที่ต้องเจอกับตัวเองถึงจะจำได้จริง
