เดือนนี้ผมตัดสินใจ open source Kasidit ซึ่งเป็น discipline framework สำหรับ Claude Code ที่ผมใช้ทำงานเองทุกวัน โดยใช้ MIT License โพสต์นี้จะเล่าว่าทำไมผมถึงเลือกเปิดแทนที่จะเก็บไว้ใช้คนเดียว ขั้นตอนที่ทำตั้งแต่ README จนถึงการติดตั้ง และสิ่งที่เรียนรู้จากการ open source โปรเจกต์แรกที่จริงจังของตัวเอง

## Kasidit คืออะไร

สั้น ๆ คือชุดกฎและเครื่องมือที่ทำให้ AI coding agent ทำงานแบบมีวินัย มี specialist agents 8 ตัวภายใต้ orchestrator ตัวเดียว ปฏิเสธงานที่ขอบเขตคลุมเครือ ติด confidence label กับข้อสรุป มี checklist สำหรับรีวิว มี runtime hooks บังคับกฎสำคัญ และเปลี่ยนทุกการแก้บั๊กหรือ deploy ให้เป็น runbook ที่ใช้ซ้ำได้

มันเริ่มจากปัญหาของผมเอง ผมเบื่อกับการที่ AI แก้เกินกว่าที่ขอ ประกาศว่าเสร็จทั้งที่ยังไม่ได้ทดสอบ และวนแก้บั๊กผีที่ไม่มีอยู่จริง ผมเลยเขียนกฎขึ้นมาใช้เอง แล้วค่อย ๆ ขยายจนเป็น framework

## ทำไมต้อง open source

**1. ถ้ามันช่วยผมได้ มันน่าจะช่วยคนอื่นได้**
ปัญหาที่ผมเจอไม่ได้พิเศษ ทุกคนที่ใช้ AI coding agent จริงจังเจอเหมือนกัน การเก็บไว้คนเดียวไม่ได้ทำให้มันมีค่าขึ้น

**2. การเปิดบังคับให้ผมทำให้ดีขึ้น**
โค้ดที่ใช้คนเดียวมีทางลัดเต็มไปหมด พอรู้ว่าคนอื่นจะอ่าน ผมต้องเขียนเอกสาร แยก config ส่วนตัวออก และทำให้ติดตั้งได้บนเครื่องที่ไม่ใช่ของผม

**3. ผมเรียนรู้จากโอเพนซอร์สมาตลอด**
ผมเริ่มเขียนโค้ดจากการอ่านโปรเจกต์ของคนอื่น นี่เป็นโอกาสแรกที่จะคืนกลับบ้าง

## ทำไมเลือก MIT

ผมอยากให้คนเอาไปใช้ได้โดยไม่ต้องคิดมาก ทั้งส่วนตัวและในบริษัท ไม่ต้องกังวลเรื่องเงื่อนไขการเปิดซอร์สต่อ MIT สั้น เข้าใจง่าย และเป็นที่รู้จัก สำหรับเครื่องมือที่อยากให้แพร่หลาย นี่คือตัวเลือกที่ตรงไปตรงมาที่สุด

## ขั้นตอนที่ทำก่อนเปิด

**ลบข้อมูลส่วนตัวและข้อมูลงานออกทั้งหมด**
ขั้นนี้ใช้เวลามากกว่าที่คิด framework ที่ผมใช้เองมี path ส่วนตัว ชื่อโปรเจกต์ และตัวอย่างที่อ้างถึงงานจริงปนอยู่ ผมไล่ค้นทุกไฟล์ แยก config ส่วนตัวออกไปไว้นอก repo และเปลี่ยนตัวอย่างทั้งหมดเป็นแบบ generic ก่อน push ครั้งแรกผมค้นหาคำที่อาจเป็น secret อีกรอบ เพราะสิ่งที่ขึ้น git history ไปแล้วเอาคืนยาก

**เขียน README ที่ตอบสามคำถามใน 30 วินาที**
- มันคืออะไร และแก้ปัญหาอะไร
- ติดตั้งอย่างไร
- ใช้ครั้งแรกอย่างไร

ผมตัดคำอธิบายแนวคิดยาว ๆ ออกจาก README ไปไว้ใน docs แยก เพราะคนที่เพิ่งเจอโปรเจกต์ยังไม่สนใจปรัชญา เขาอยากรู้ว่ามันใช้ได้ไหม

**ทำให้ติดตั้งได้ในไม่กี่คำสั่ง**
Kasidit ติดตั้งเป็น plugin ของ Claude Code ได้โดยตรง

```bash
# In Claude Code
/plugin marketplace add kasidit-wansudon/kasidit
/plugin install kasidit@kasidit
```

หรือ clone repo แล้วรันสคริปต์ติดตั้ง ซึ่งผมทำให้ idempotent คือรันซ้ำได้โดยไม่พัง

```bash
git clone https://github.com/kasidit-wansudon/kasidit.git
cd kasidit
bash plugins/kasidit/install.sh
```

การทำให้สคริปต์รันซ้ำได้สำคัญมาก เพราะผู้ใช้จะรันซ้ำแน่นอนเวลาอัปเดต หรือเวลาติดตั้งครั้งแรกแล้วไม่แน่ใจว่าสำเร็จ

## หาผู้ใช้กลุ่มแรก

ผมไม่ได้มีงบโฆษณา และไม่ได้คาดหวังว่าจะมีคนเข้ามาเอง สิ่งที่ทำคือ

- ใช้เองทุกวันต่อไป และแก้ปัญหาที่เจอทันที เพราะผู้ใช้คนแรกที่สำคัญที่สุดคือตัวเอง
- แบ่งปันกับเพื่อน developer ที่ใช้ Claude Code อยู่แล้ว และขอ feedback ตรง ๆ ว่าติดตรงไหน
- ทำเว็บไซต์ [kasi.kasion.dev](https://kasi.kasion.dev) ที่อธิบายแนวคิดสั้น ๆ พร้อมลิงก์ไป repo
- เขียนบทความแบบนี้ เล่าปัญหาที่มันแก้ แทนการโปรโมตตัวเครื่องมือ

feedback ที่มีค่าที่สุดในช่วงแรกไม่ใช่คำชม แต่คือ "ติดตั้งแล้วไม่รู้ว่าต้องทำอะไรต่อ" มันทำให้ผมเพิ่มส่วน quick start และคำสั่งเริ่มต้นแบบตอบคำถามเดียว

## วัดผลให้เป็นตัวเลข

ผมไม่อยากให้ framework นี้ขายด้วยความรู้สึก จึงทดสอบกับ SWE-bench เทียบกับการไม่ใช้ framework ผลคือแก้โจทย์ได้ 75% เทียบกับ 63% ตัวเลขนี้ช่วยตอบคำถามแรกที่ทุกคนถามว่า "มันช่วยได้จริงหรือ" รายละเอียดผมเขียนไว้ใน [Kasidit กับ SWE-bench 75%](/blog/kasidit-swe-bench-75-percent)

## สิ่งที่ได้เรียนรู้

- **เอกสารสำคัญเท่ากับโค้ด** ฟีเจอร์ที่ไม่มีใครรู้ว่ามีอยู่ ก็เหมือนไม่มี
- **ค่าเริ่มต้นต้องปลอดภัยและเบา** ผู้ใช้ใหม่ไม่ควรเจอ framework เต็มรูปแบบทันที ผมจึงทำ mode หลายระดับให้เลือก
- **อย่าเปิดเผยมากกว่าที่ตั้งใจ** ตรวจ secret และข้อมูลงานก่อนทุก push
- **ปล่อยเร็วกว่าที่รู้สึกว่าพร้อม** ถ้ารอให้สมบูรณ์ คงไม่ได้ปล่อยเลย feedback จริงสอนได้มากกว่าการขัดเกลาคนเดียว

## สรุป

ผม open source Kasidit เพราะปัญหาที่มันแก้เป็นปัญหาร่วมของคนที่ใช้ AI coding agent และเพราะการเปิดบังคับให้ผมทำมันให้ดีขึ้น เลือก MIT เพื่อให้ใช้ได้ง่ายที่สุด ทำความสะอาดข้อมูลส่วนตัวก่อนเปิด เขียน README ที่ตอบคำถามได้ในไม่กี่วินาที ทำให้ติดตั้งได้ในไม่กี่คำสั่ง แล้วฟัง feedback จากผู้ใช้กลุ่มแรกอย่างจริงจัง ถ้าคุณมีเครื่องมือที่ใช้เองอยู่ทุกวัน ลองคิดดูว่ามันอาจช่วยคนอื่นได้เหมือนกัน
