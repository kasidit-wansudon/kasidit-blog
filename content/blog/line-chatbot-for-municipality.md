ทุกคนมีงานแรกที่ได้เงินจากการเขียนโค้ด ของผมคือ LINE chatbot สำหรับรับเรื่องร้องเรียนของเทศบาลเมืองศรีสะเกษ ทำแบบ freelance ในปี 2021 ตอนที่ยังเรียนสาขา Software Engineering อยู่ที่มหาวิทยาลัยราชภัฏศรีสะเกษ มองย้อนกลับไป งานนี้สอนผมมากกว่าวิชาไหน ๆ ในห้องเรียน ไม่ใช่เพราะเทคนิคยาก แต่เพราะเป็นครั้งแรกที่มีคนใช้สิ่งที่ผมสร้างจริง ๆ

## โจทย์: ให้ประชาชนแจ้งเรื่องได้ง่ายที่สุด

คนในเมืองใช้ LINE กันเป็นประจำอยู่แล้ว การให้แจ้งเรื่องผ่าน LINE chatbot จึงง่ายกว่าการให้โหลดแอปใหม่หรือเข้าเว็บ ระบบที่ทำมีสามส่วนหลัก

1. **LINE chatbot** ให้ประชาชนส่งเรื่องร้องเรียน พร้อมรูปและตำแหน่ง
2. **AI กรองเรื่อง** คัดข้อความที่ไม่ใช่เรื่องร้องเรียนจริงออก เช่น ข้อความทักทาย ข้อความไม่เกี่ยวข้อง หรือข้อความไม่สุภาพ
3. **Dashboard และขั้นตอนอนุมัติ** ให้เจ้าหน้าที่ตรวจ อนุมัติ และติดตามสถานะของแต่ละเรื่อง

## ทำไมต้องมี AI กรอง

ตอนเริ่มผมคิดว่าทุกข้อความที่ส่งเข้ามาคือเรื่องร้องเรียน แต่ในความจริง ช่องทางที่เปิดให้ทุกคนพิมพ์ได้จะมีข้อความหลากหลายมาก ถ้าส่งทุกข้อความเข้า dashboard เจ้าหน้าที่จะจมอยู่กับข้อความที่ไม่ต้องทำอะไร และเลิกใช้ระบบในที่สุด

AI ในงานนี้จึงทำหน้าที่เป็นด่านแรก ไม่ใช่ผู้ตัดสินใจ ข้อความที่ผ่านด่านไปแล้วยังต้องให้เจ้าหน้าที่อนุมัติอีกชั้น นี่คือบทเรียนสำคัญที่ผมยังใช้อยู่ทุกวันนี้: ให้ AI ช่วยลดงาน แต่ให้คนเป็นผู้ตัดสินในเรื่องที่มีผลกับผู้อื่น

## พื้นฐานของ LINE webhook ที่มือใหม่ต้องรู้

เมื่อผู้ใช้ส่งข้อความหา bot, LINE จะส่ง webhook มาที่ server ของเรา สิ่งแรกที่ต้องทำคือยืนยันว่า request มาจาก LINE จริง ด้วยการตรวจ signature ใน header `x-line-signature` ซึ่งคือ HMAC-SHA256 ของ body ด้วย channel secret แล้ว encode เป็น base64

```js
const crypto = require('crypto');

function isValidLineSignature(rawBody, signature, channelSecret) {
  const expected = crypto
    .createHmac('sha256', channelSecret)
    .update(rawBody)
    .digest('base64');
  const a = Buffer.from(expected);
  const b = Buffer.from(signature || '');
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

จุดที่มือใหม่พลาดบ่อย รวมถึงผมเองในตอนนั้น คือการตรวจ signature จาก body ที่ถูก parse เป็น JSON แล้ว ต้องใช้ raw body ตามที่ได้รับมาเท่านั้น ไม่เช่นนั้น signature จะไม่ตรง

อีกเรื่องคือ webhook ควรตอบกลับเร็ว ถ้ามีงานหนัก เช่น เรียก AI หรือบันทึกรูป ควรรับเรื่องไว้ก่อนแล้วค่อยประมวลผลต่อ แทนที่จะให้ LINE รอ

## สิ่งที่มือใหม่ได้เรียนจากลูกค้าจริง

### 1. ผู้ใช้จริงไม่ได้ใช้ตามที่เราคิด

ผมออกแบบ flow ให้ส่งรูปก่อน แล้วค่อยพิมพ์รายละเอียด แต่ผู้ใช้จริงส่งทุกอย่างสลับลำดับกัน บางคนพิมพ์ยาวในข้อความเดียว บางคนส่งรูปหลายใบโดยไม่พิมพ์อะไรเลย ระบบต้องยืดหยุ่นพอจะรับได้ทุกแบบ

### 2. ผู้ใช้มีสองกลุ่ม และสำคัญเท่ากัน

ประชาชนคือผู้ใช้ที่เห็นชัด แต่เจ้าหน้าที่ที่ใช้ dashboard ทุกวันคือคนที่จะทำให้ระบบอยู่รอดหรือถูกทิ้ง ถ้า dashboard ใช้ยาก เรื่องจะค้าง และประชาชนก็จะเลิกแจ้ง

### 3. "เสร็จ" ของ developer ไม่ใช่ "เสร็จ" ของลูกค้า

ผมคิดว่างานเสร็จเมื่อโค้ดทำงาน แต่สำหรับลูกค้า งานเสร็จเมื่อเจ้าหน้าที่ใช้เป็นและระบบไม่ล่มในวันที่มีเรื่องเข้ามาเยอะ ผมได้เรียนรู้ว่าต้องเผื่อเวลาสำหรับการสอนใช้งาน การแก้ตามความเห็น และการดูแลหลังส่งมอบ

### 4. สื่อสารด้วยภาษาของลูกค้า

ลูกค้าไม่สนใจว่าใช้ webhook หรือ database อะไร เขาสนใจว่าเรื่องร้องเรียนจะถึงมือเจ้าหน้าที่ภายในกี่นาที และจะติดตามสถานะได้อย่างไร การเล่าด้วยภาษาของผลลัพธ์ทำให้คุยกันง่ายขึ้นมาก

## สิ่งที่ผมจะทำต่างไปถ้าย้อนเวลาได้

- เขียนเอกสารการใช้งานสั้น ๆ ตั้งแต่วันแรก
- มี log ที่อ่านง่ายสำหรับไล่ปัญหาในวันที่ระบบมีปัญหา
- ตกลงขอบเขตงานเป็นลายลักษณ์อักษรให้ชัดก่อนเริ่ม เพื่อไม่ให้งานงอกโดยไม่รู้ตัว

ช่วงเดียวกันผมยังได้ทำงาน freelance อีกชิ้นคือเชื่อม payment gateway ให้โรงพยาบาลแห่งหนึ่งด้วยการเข้ารหัส RSA ซึ่งสอนให้ผมระวังเรื่องความปลอดภัยตั้งแต่ต้นอาชีพ ก่อนหน้านั้นผมทำงานด้านโลจิสติกส์และงานก่อสร้าง เรื่องนั้นผมเล่าไว้ใน [จากงานโลจิสติกส์และก่อสร้างสู่การเขียนโค้ด](/blog/from-logistics-to-code)
